Otvoren-Vot · End-to-End Verifiable E-Voting

Two-Layer System Architecture

Privacy by separation. Layer 1 knows who voted but never sees ballot content. Layer 2 sees encrypted ballots but never learns voter identity. No single component can link a ballot to a voter.

Voter Interfaces — Client-side encryption and ZK proof generation
🌐
Web App
TypeScript / React — izbori.bg
Voter-facing UI. All encryption happens in-browser using ElGamal over Ristretto255 via libsodium.js WASM. Generates ZK validity proofs and random 256-bit ballot IDs client-side.
🖥️
Voting Machine
Go / Embedded Linux — TPM attested
Polling station kiosk. Hardware-verified boot via TPM. Encrypts ballots with same Go crypto library as servers. Offline-first with SQLite queue and signed USB fallback.
🔌
Browser Extension
TypeScript — Manifest V3
Malware detection via threshold return codes. Runs in isolated service worker — page JS cannot access it. Pins TLS cert and checks page script hash independently.
encrypted ballot + ZK proofs + eAuth session
Layer 1 — Identity Knows WHO, not WHAT
🔑
Auth Service
Go — eAuth 2.0 / SAML 2.0
Authenticates voters via Bulgarian national eAuth. Validates identity, checks eligibility against electoral rolls, issues JWT session tokens (30 min TTL). Ships with mock eAuth for development.
✓ Voter ЕГН, eligibility, session
✗ Never sees ballot content
📮
Collection Server
Go — Identity stripping gateway
Receives encrypted ballots. Records ЕГН → ballot_id mapping. Strips ALL identity (ЕГН, session, IP, headers) before forwarding to Layer 2. Returns Merkle inclusion proof to voter.
✓ Who voted, which ballot_id is theirs
✗ Forwards encrypted ballot without reading it
Network Isolation — Hardware firewalls in production
→
One-time handoff at polls close (20:00). Layer 1 computes the active ballot ID set (one per voter, most recent) and delivers it to the Tally Service. Only ballot_ids cross the boundary — no ЕГНs, no voter data. Requires dual-operator approval from two ЦИК administrators. No return path — Layer 2 can never query Layer 1.
Layer 2 — Ballots Knows WHAT, not WHO
📋
Bulletin Board
Go + PostgreSQL — Public ledger
Append-only Merkle tree. Dual-hash: SHA-256 for public verification, Poseidon/BN254 for SNARK circuits. Publishes signed root every 60 seconds. Fully public read API.
✓ All encrypted ballots and ZK proofs
✗ No voter identity — only random 256-bit IDs
🧮
Tally Service
Go — gnark Groth16 + Ristretto255
Homomorphic tallying — ciphertext multiplication, no ballot decrypted. Generates ZK dedup proof (gnark SNARK). Coordinates 5-of-9 threshold decryption ceremony with trustee HSMs.
✓ Active set of ballot IDs, encrypted sums
✗ No voter identity — receives only ballot IDs
🛡️
Verification Service
Go — 3-of-5 threshold return codes
Generates per-session verification codes via threshold trustees. Validates blinded session tokens (RFC 9474) — authenticates extension sessions without learning voter identity.
✓ Encrypted ballot content for code derivation
✗ Blinded tokens — cannot link session to voter
public read API — all election data openly accessible
Public Verification & Transparency — Anyone can independently verify the election

Public Dashboard
TypeScript / React — CDN
Live ballot count, ceremony progress, results with charts. Streams trustee contributions in real-time during the televised decryption ceremony.
✓
Verification Portal
verify.izbori.bg
Enter ballot ID, receive Merkle inclusion proof. Confirms your ballot was counted without revealing contents. Inclusion only, never content.
⚙️
CLI Verification
otvoren-vot verify all
Full independent audit: rebuild Merkle tree, verify all ballot proofs, check dedup SNARK, verify partial decryptions, recompute tally from scratch.

Key Principle

No single component — and no single insider — can both identify a voter and learn how they voted. Voter identity exists only in Layer 1. Ballot content exists only in Layer 2. Network-level separation ensures that even a fully compromised service in either layer cannot breach the other.
