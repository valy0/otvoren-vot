Otvoren-Vot · End-to-End Verifiable E-Voting

Verification & Trust Chain

Three levels of verification ensure no trust in any single entity is required. Four independent cryptographic proofs cover every step from ballot submission to final results. If the proofs verify, the results are correct.

Three Levels of Trust
1
Immediate

Return Code Verification

During voting — within seconds of submission

Browser extension displays a 6-digit return code derived by 3-of-5 verification trustees. If it matches the pre-loaded code mapping, the voter knows their intended ballot was correctly encrypted and recorded — even if the voting page was compromised.

Who: The voter, via browser extension popup
2
Individual

Ballot Inclusion Check

Post-election — at verify.izbori.bg

Enter your ballot ID and receive a Merkle inclusion proof confirming your ballot is in the active counted set. This is an inclusion-only proof — confirms the ballot was counted without revealing contents. A voter cannot prove to a third party what they voted for.

Who: Any voter who saved their ballot ID
3
Full Audit

Full Independent Verification

Post-ceremony — via CLI tools or custom code

Download the entire bulletin board. Rebuild the Merkle tree. Verify every ballot proof. Check the dedup SNARK. Verify all trustee Chaum-Pedersen proofs. Recompute the tally from raw data. Confirm results match.

Who: Political parties, NGOs, universities, media, any citizen
Four Cryptographic Proofs
P1

Ballot Validity

Sigma Protocol (OR-proof + sum-proof)

Every accepted ballot encodes exactly one party choice and at most one candidate preference, using only 0/1 values. Attached to each ballot at submission time.
